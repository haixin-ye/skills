# Stage 3: Technical Path And Handoff

Stage 3 begins only after the user elects to pursue the idea.

## Technical path comparison

For each realistic path, document:

- Core mechanism and dependencies
- Required external services, hardware, accounts, credentials, or permissions
- Compatibility with hard constraints
- Performance and scalability considerations
- Development and maintenance complexity
- Security, privacy, and licensing implications
- What a first proof-of-concept must prove

Choose a recommendation only after comparing meaningful alternatives. If only one realistic route exists, explain why alternatives were eliminated.

## Handoff contract

The future development agent must receive enough information to start planning without repeating basic discovery. Include:

- Product summary and user value
- Confirmed requirements, hard constraints, and explicit non-goals
- Validated facts and their source IDs
- Assumptions and environment-dependent open questions
- Existing solutions and differentiation
- Selected/recommended path and rejected alternatives
- Preliminary architecture and module responsibilities
- MVP scope and acceptance criteria
- Ordered PoC tasks
- Risks, decision status, and what requires user confirmation before implementation

Do not write instructions that imply implementation has been approved if it has not.
