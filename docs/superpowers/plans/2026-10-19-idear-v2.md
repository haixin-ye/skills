# Idear v2 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Upgrade Idear into an adaptive-depth, decision-tree-driven product-discovery skill while preserving its evidence, feasibility, and development-handoff strengths.

**Architecture:** Keep `skills/idear/SKILL.md` as the concise orchestrator. Route requests to quick, focused, or full depth before creating artifacts; use a persisted decision tree for full discovery; keep stage-specific mechanics in references and output schemas in templates. Behavioral scenarios prove routing and decision-quality changes, while the existing repository validator proves bundle integrity.

**Tech Stack:** Agent Skills Markdown/YAML, JSON catalog metadata, Python structural validator, GitHub Actions, independent agent behavior evaluations.

### Task 1: Capture RED behavioral baseline

**Files:**
- Create: `tests/idear/behavior-scenarios.md`

- [ ] Run the current skill against a bounded factual request, a focused technical investigation, and a complex full-discovery request.
- [ ] Record only observed failures: unnecessary workspace creation, inability to perform a focused assessment, non-deterministic high-value question selection, missing dependency/invalidation state, or weak completion gates.
- [ ] Write the scenario assertions before changing the skill:

```markdown
| Scenario | Required observable behavior |
| --- | --- |
| Bounded fact | Answer directly; do not create an idea workspace unless requested. |
| Focused investigation | Research only the named uncertainty; provide sources and a smallest validation; do not force full product definition. |
| Complex rough idea | Create a full workspace, classify critical nodes, and ask only frontier questions. |
| Constraint reversal | Mark dependent conclusions stale or superseded and report affected artifacts. |
| Existing definition | Enter the earliest incomplete stage without repeating settled discovery. |
```

- [ ] Confirm at least one assertion fails against v1 and preserve the evidence in the test document.
- [ ] Commit the baseline scenarios separately.

### Task 3: Add the persisted decision tree

**Files:**
- Create: `skills/idear/references/decision-tree.md`
- Modify: `skills/idear/assets/templates/project-context.yaml`
- Modify: `skills/idear/references/stage-1-clarification.md`
- Modify: `skills/idear/assets/templates/product-definition.md`

- [ ] Add failing assertions for dependency ordering, fact-versus-decision ownership, and constraint-reversal invalidation.
- [ ] Define node kinds exactly as `user_decision`, `fact`, `assumption`, `experiment`, and `constraint`.
- [ ] Define statuses exactly as `open`, `resolved`, `assumed`, `needs_research`, `needs_poc`, `deferred`, `out_of_scope`, `stale`, and `superseded`.
- [ ] Persist for each material node: `id`, `question`, `kind`, `depends_on`, `status`, `resolution`, `impact`, and `evidence_refs`.
- [ ] Define the frontier as open material nodes whose prerequisites are settled.
- [ ] Rank frontier nodes by downstream blocking impact, potential to change the verdict, hard-constraint relevance, irreversibility, uncertainty, and user answerability.
- [ ] Ask one question by default; ask up to three only when independent and easy to answer.
- [ ] Require the agent to research facts, ask the user for value choices, label assumptions, and route environment-dependent outcomes to PoC.
- [ ] On an upstream change, mark dependent conclusions `stale`, preserve replaced decisions as `superseded`, and name affected artifacts to the user.
- [ ] Complete Stage 1 only when every high-impact node is resolved, assumed, delegated to research/PoC, deferred, or out of scope and the user confirms the summary.
- [ ] Re-run full and reversal scenarios; verify the new assertions pass.
- [ ] Commit decision-tree behavior.

- [ ] Re-run focused and full research scenarios; verify irrelevant broad research is not required.
